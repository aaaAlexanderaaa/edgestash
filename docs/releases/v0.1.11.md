# EdgeStash 0.1.11 — Delayed minimize and recovery request ordering

This non-latest prerelease fixes delayed window writes and preserves the newest
named request while screen-set recovery confirms its presentation. It continues
the Release-optimized diagnostic package used by 0.1.10.

## Changes

- Keep stash ownership, restore geometry and acknowledged rescue records while
  an accepted minimize awaits actual completion. Repeated shortcuts keep their
  newest target through the existing bounded confirmation and recovery path.
- Serialize named reveal/collapse requests during recovery readback. A stale
  not-minimized read cannot be mistaken for a system-owned Dock restore. After
  confirmation, the newest request runs after the coordinator commits; newer
  input, failure or environment cancellation invalidates an older replay.
- Give recovery frame and opacity writes bounded read-only confirmation without
  repeating the writes or spending another attempt. Persistent mismatch still
  uses the existing fallback and bounded retry policy.
- Preserve distinct fallback origins across separately due recovery batches.
  Reject minimized or invalid AX bounds as saved placement or resize evidence.
- Add the session recovery/request replay to CI, covering delayed minimize,
  consecutive toggles, confirmation timeout and cancellation, Space-safe reveal,
  same-target retries and superseded deferred callbacks.

## Install and test

1. Download `EdgeStash.zip` from this release.
2. **Quit the running EdgeStash first**, allowing managed windows to restore.
   Extract the archive, replace the app and reopen it. Source builds use
   `dist/EdgeStash.app`; `dist/CURRENT.txt` records the package details.
3. Check Stickies capture/reveal/collapse, repeated shortcuts during recovery,
   display unplug/replug and display/system sleep-wake. If a symptom recurs,
   record its time and promptly copy `~/Library/Logs/EdgeStash/`.

Apple Silicon only. Outer edges require macOS 12 or later; shared seams require
macOS 26.4 or later and supported runtime capabilities. This package uses Release
optimization with bounded local diagnostics enabled. Logs contain no window
titles, document contents, keystrokes or pixels and are never uploaded automatically.

The app is ad-hoc signed and unnotarized, with no installable Homebrew Cask.
Accessibility may need to be granted again after updating. This is a prerelease;
the existing latest release remains unchanged.

## Verification scope

- Expectation check and full logic suite, including 18,432 configured three-display
  round trips and 1,512 subset-return paths. Twelve presentation anchors remain
  declared; cardinality coverage is one executable and eleven structural-only rows.
- Current live coordinator replay: 68 timelines and 306 assertions.
- Current session recovery/request replay: 35 assertions across 19 method bodies,
  with injected AX/UI, clock, main queue, animation, observer and coordinator
  boundaries. Removing the recovery busy gate makes the regression fail.
- Existing session-write replay: 18 assertions. Native isolated persistence and
  own-AppKit control checks, ten distribution-tool tests, CLT Debug and diagnostic
  Release builds. These do not prove cross-app AX completion.
- The exact release commit's full Xcode-project Debug validation must pass in
  GitHub Actions before publication; its final run is linked in the release body.

Physical macOS 27 multi-display sleep/wake, cross-app AX/input, WindowServer
performance and owner perceptual acceptance remain open. The field log's opacity
symptom is not claimed fixed solely by adding a bounded readback wait.
