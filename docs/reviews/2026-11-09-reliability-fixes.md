# EdgeStash 0.1.9 可靠性修复与验证

本轮修复救援记录丢失、环境恢复绕过 Space 检查、快捷键与 Dock 输入误判，以及
无障碍操作缺口。行为依据是 owner 接受的
[恢复与输入契约](../contracts/reliability-and-input-sources.md)。
交付为 0.1.9（10）的 arm64 Release 诊断包，本地 ad-hoc 签名。
macOS 27 三屏休眠后的丢失收纳与持续 WindowServer 负载仍需现场验证。

## 已实现的修复

| 范围 | 当前行为 |
| --- | --- |
| 救援持久化 | 隐藏前必须确认救援保存。独立的两个 rescue 文件保存同一完整最新集合；普通设置损坏不再连带丢弃救援。未知枚举和单个坏应用配置局部降级。读失败不能视为空集合，旧读取者不能覆盖未观察过的记录；同进程比较和写入串行化。实际失败显示在现有系统设置页。 |
| 环境恢复 | 展开的接缝窗口恢复，以及接缝变成外缘时的停放转换，共用普通展开的 Space 准备与提交过程。拒绝或提交失败时保留最小化及原始意图；取消最小化后的失败尝试补偿。旧目标回调不能完成新目标，同一目标不丢失完成通知。 |
| 最小化确认 | 写入后的未知状态不再算成功。失败保留可见性恢复责任；暂时控制失效沿用有界重试。外观正确但救援保存失败单独保留待恢复状态，不回退到桌面。 |
| 收纳与应用快捷键 | 拖动、应用快捷键、临时快捷键共用标准窗口准入条件。已有收纳时先操作配置的收纳范围；仅在没有收纳时捕获普通窗口。临时快捷键不会使对话框或面板变得可收纳。 |
| Cmd Tab 与 Dock | 任意激活不再推断成 Cmd-Tab。必须观察到相符按键及 Command 释放；取消、其他按键、指针动作和过期会清除意图。Dock 标题回退仅限唯一匹配；焦点路径要求已知应用与实际窗口身份变化。 |
| 展开所有窗口 | 菜单提供显式“展开所有收纳窗口”。移除硬编码 Control 方向键推断；Mission Control、App Exposé、手势、触发角和硬件按键不承诺自动触发展开。 |
| 无障碍与设置 | 边缘信号、合并条分段和固定按钮可通过无障碍 press 操作；固定按钮提供复选状态。修正 G、H、B 键名。 |
| 工程验证 | 修正 Cask 最低系统声明，加入原生适配器检查及 GitHub Actions。契约检查增加能力边界和 AppKit 分层检查。 |

没有新增网络、截屏或权限能力，没有导入外部实现。保存确认涵盖进程失败恢复；
不承诺任意硬件故障或突然断电后的存储持久性。

## 实机验收与后续方向

先退出正在运行的 EdgeStash，再打开仓库的 `dist/EdgeStash.app`；跨机器使用
`dist/EdgeStash.zip`。`dist/CURRENT.txt` 记录配置与构建时间。

1. 优先在 macOS 27 三屏环境重放休眠与唤醒，确认原信号、展开与固定意图保留；
   同时采集已有本地诊断，区分控制暂不可用、Space 拒绝、真正的窗口关闭和进程重启。
2. 复核接缝窗口展开、跨 Space 受拒及显示器拓扑变化；拒绝时应保持最小化，
   不应从桌面回退路径出现。检查健康窗口不会被环境恢复额外移动。
3. 验收 Cmd-Tab 提交与取消、重复标题的 Dock 缩略图、普通窗口和收纳窗口混合的
   应用快捷键，以及 VoiceOver 操作。输入来源无法确认时保持收纳关闭。
4. 继续将行为语法中仅有结构证据的次数约束转成可执行的生命周期验证。
   若要承诺系统 Mission Control 的全部入口，应先确定可可靠观察的边界并更新契约。
5. 正式分发仍需 owner 的许可证选择、Developer ID 与公证验收。2026-11-09 的
   本地交付未提交或发布；2026-11-10 owner 明确要求提交、构建、推送和发布，
   沿用 `v0.1.8` 的诊断预发布渠道，不登记为正式签名发行版。
